SITE RELEASE MANAGER — CREATE TRANSFER 7Z

The archive name contains the project folder name plus the current date/time.
All .env / .env.* files are INCLUDED.
Every node_modules folder is EXCLUDED.

============================================================
macOS / zsh
============================================================
Run from the ROOT of the site-release-manager project:

project="$(basename "$PWD")"; stamp="$(date '+%Y-%m-%d_%H-%M-%S')"; sevenzip="$(command -v 7zz || command -v 7z)"; if [ -z "$sevenzip" ]; then echo "7-Zip was not found (expected 7zz or 7z)"; return 1 2>/dev/null || exit 1; fi; "$sevenzip" a -t7z "../${project}_${stamp}.7z" . -xr'!node_modules' -xr'!node_modules/*' -xr'!*/node_modules' -xr'!*/node_modules/*'

Example:
site-release-manager_2026-08-10_15-30-45.7z

============================================================
Windows / PowerShell
============================================================
Run from the ROOT of the site-release-manager project:

$project = Split-Path -Leaf (Get-Location); $stamp = Get-Date -Format 'yyyy-MM-dd_HH-mm-ss'; & 'C:\Program Files\7-Zip\7z.exe' a -t7z "..\${project}_${stamp}.7z" ".\*" '-xr!node_modules' '-xr!node_modules\*' '-xr!*\node_modules' '-xr!*\node_modules\*'

The archive intentionally keeps .env because the current closed-Windows transfer
workflow needs the environment configuration inside the whitened package.
